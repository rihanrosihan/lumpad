New routes (GET only): `/api/plan/status`, `/api/plan/range?from&to`, `/api/plan/day?date`.

Known limit: `PLAN` is loaded once per process. That is correct while the active version never changes (P1/P2). P3 must move readers to a per-call accessor before any patch is activated.

Client opt-in for testing before G3 (does not change what other users see): open the app once with `?plan=api`, or set `localStorage.lumpad.planApi='1'`; after the first refresh the device serves the cached server plan. Remove the key to go back. A `lumpad:plan-changed` window event fires when the server plan differs (P3 can show an update banner).

Flip procedure after G3 passes: set `PLAN_SOURCE=engine` in the service environment, restart `lumpad`, check `/api/plan/status` shows `source: engine, version: 1`; rollback = unset and restart.
